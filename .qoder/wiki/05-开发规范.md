# 05 开发规范

> 迁移自原公共知识库 `03-dev-conventions.md`，并合并提交前检查，2026-11-18 核实。

## 添加新功能流程

### Rust 后端工具

1. 在 `src/services/tools/` 创建服务文件实现业务逻辑，并在 `src/services/tools/mod.rs` 导出
2. 在 `src/models/` 创建对应的请求/响应模型（serde `Deserialize`/`Serialize`）
3. 在 `src/routes/tools/` 创建路由文件并在 `src/routes/tools/mod.rs` 中挂载

### Rust 后端 Agent 功能

在 `src/services/agents/` 与 `src/routes/agents/` 对应文件中扩展；新业务可新建文件并在各自 `mod.rs` 导出/挂载。例：新 LLM 提供方在 `services/agents/` 下新建客户端文件，参照 `llm.rs` 的 `is_configured / chat_stream / chat_complete` 模式。

### Python 后端接口

1. 在 `app/services/` 对应域实现业务逻辑
2. 在 `app/schemas/request/`、`app/schemas/response/` 添加模型
3. 在 `app/api/v1/endpoints/` 添加或扩展路由，并在该目录 `__init__.py` 聚合
4. 对照 [09-API契约与路由](09-API契约与路由.md)，标注与 Rust 的兼容程度；未实现兜底时也要更新路由覆盖矩阵

### 前端工具

1. 在 `src/views/ViewFront/`（浏览器端）或 `src/views/ViewBack/`（服务器端）创建 Vue 组件
2. 在 `src/router/index.ts` 的 `routeDefs` 中登记一行（view 为 views/ 相对路径）
3. 在 `src/services/api.ts` 的 `ApiService` 中添加 API 调用（统一走 `requestWithFallback`；流式请求参照 `chatStream`）
4. 在 `tools` 表登记数据（含 `route`）并同步 `/tools/categories` 展示数据；`ToolView.vue` 跳转优先读工具数据的 `route`，缺失时回退按工具 ID 的路由映射；后端工具还会经过 `healthCheck()` 门禁

## 代码风格

- Rust：axum 路由 + handler 返回 `Json<BaseResponse<T>>`；配置统一走 `core::config::SETTINGS`（`once_cell::Lazy` + `envy` 读环境变量）；异步基于 tokio；DB 用 sqlx（PostgreSQL，可选）
- 前端：Vue 3 Composition API + TypeScript，UI 用 Ant Design Vue；HTTP 统一走 `ApiService`；流式用 `adapter: 'fetch'` + `responseType: 'stream'` 手动解析 SSE
- 遵循现有文件的代码风格与目录组织方式，不要随意引入新依赖
- 及时清理无用代码（未引用的文件/导出/变量），保持代码简洁

## 提交前检查

- 前端：必跑 `yarn build`，确认 vue-tsc 类型检查通过
- Rust：必跑 `cargo check`（或 `cargo build`），确认编译通过
- Python：当前无统一测试/lint 命令，需按改动接口做实际请求验证，并核对双端兼容性

## 文档与履历维护

- 完成代码修改后，同步更新 `.qoder/wiki/` 中受影响文档，并在项目根 `修改履历.md` 追加记录（修改时间、业务需求、涉及模块、修改内容、备注）
- 新增/修改后端接口时原则上双端同步实现；若暂不同步，必须在 [09-API契约与路由](09-API契约与路由.md) 的路由覆盖矩阵标注能力差异

## 注意事项

- Rust 数据库未连接时以无 DB 模式启动，Agent 和多数认证接口会报错，不会自动降级为等价功能；Python 自 2026-11-06 起有 asyncpg 懒加载连接池（仅 admin 接口使用），DB 未配置时 admin 接口返回 500「数据库连接池未初始化」
- 项目目前缺少自动化测试，认证与第三方绑定也存在明确的未闭环能力，改动时查阅 [07-后端架构-Rust](07-后端架构-Rust.md) 与 [08-后端架构-Python](08-后端架构-Python.md) 的现状说明
- 不要提交任何密钥、API Key 或 `.env` 文件
