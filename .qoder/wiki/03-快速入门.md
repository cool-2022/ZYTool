# 03 快速入门

> 整合原公共知识库 `02-commands.md`，2026-11-18 核实。

## 环境要求

| 端 | 要求 |
|---|---|
| Rust 后端 | Rust toolchain（edition 2024，建议 rustup 最新 stable） |
| Python 后端 | Python 3.9+ |
| 前端 | Node.js 20.19+（Vite 7 要求）+ yarn 1.22.x |
| 可选基础设施 | PostgreSQL（`zytool` 库，需先手工执行 `ToolsAI/zytool.sql`）、Redis |

DB / Redis 均可选：连接失败时服务以降级模式继续运行（详见 [01-系统概述](01-系统概述.md)）。

## 启动顺序

推荐：PostgreSQL / Redis → Rust 后端 → Python 后端 → 前端。

## 后端 Rust（Backup/tools_project_rust/）

```bash
./start.sh           # 前台运行（debug 二进制看门狗，异常退出 1 秒后重启，Ctrl+C 停止）
./start.sh -d        # 后台守护运行（日志 logs/server.log，PID logs/watchdog.pid）
./start.sh stop      # 停止看门狗与后端进程

cargo run              # 直接启动（无守护），监听 .env PORT（当前 10003，源码默认 8000）
cargo build            # 编译（类型检查）
cargo build --release  # 生产构建（opt-level 3 + LTO）
cargo check            # 快速类型检查
cargo run -- encrypt-key <明文>   # 工具子命令：加密模型 API Key
```

**注意**：`start.sh` 只有 debug 二进制不存在时才自动 build；修改源码后必须显式 `cargo build`，看门狗重启不会自动重编译。

## 后端 Python（Backup/tools_project_py/）

```bash
python3 -m pip install -r requirements.txt
python3 run.py   # 端口取 .env 的 PORT=10004
```

源码默认端口为 8000；`start_server.sh` 已改为调用 `python3 run.py`，端口统一由 config/.env 决定，不再硬编码。

## 前端（ZYTool/）

包管理器统一使用 **yarn**（1.22.x），不要用 npm，避免生成 package-lock.json 与 yarn.lock 双锁文件冲突。

```bash
yarn          # 安装依赖
yarn dev      # 启动开发服务器 http://localhost:5050（热重载）
yarn build    # vue-tsc 类型检查 + 生产构建（提交前必跑，作为 typecheck）
yarn preview  # 预览生产构建
yarn add <pkg>        # 新增依赖（开发依赖用 yarn add -D <pkg>）
```

当前没有 test、lint 或独立 typecheck 脚本，也没有项目测试文件；`yarn build` 是唯一类型检查入口。`start` 脚本有 `yarn rnu dev` 拼写错误，使用 `yarn dev`。

## 验证安装成功

| 检查项 | 方式 | 预期 |
|---|---|---|
| Rust 存活 | `curl http://localhost:10003/health` | 统一响应结构 `success=true` 且含 version |
| Python 存活 | 访问 `http://localhost:10004/api/v1/health` | 200（原始业务结构） |
| 前端 | 打开 `http://localhost:5050` | 登录页正常；`/home` 首页、工具分类加载成功 |
| 降级链路 | 停掉 Rust 后使用前端工具 | 网络错误 / 5xx 类请求自动转 Python（4xx 不降级） |

## 常见问题

1. **端口被占用**：`lsof -i :10003`（或 10004 / 5050）定位进程后 kill。本机 8000 常被微信等占用，这是双后端迁至 10003 / 10004 的原因
2. **改了 Rust 代码没生效**：看门狗不会重编译，需显式 `cargo build` 后重启
3. **yarn start 报错找不到命令**：`start` 脚本有 `yarn rnu dev` 拼写错误，用 `yarn dev`
4. **Agent / 认证接口 500 但 DB 无关工具可用**：DB 未连接，Rust 处于无 DB 模式；DB 恢复后需重启 Rust 进程（Python 侧为懒加载，无需重启）
5. **不要用 npm install**：会生成 package-lock.json，与入库的 yarn.lock 形成双锁文件冲突
6. **天气工具 403 Invalid Host**：和风新控制台账号必须在两端 `.env` 配置专属 `QWEATHER_HOST`

## 提交前检查

- 前端：必跑 `yarn build`，确认 vue-tsc 类型检查通过
- Rust：必跑 `cargo check`（或 `cargo build`），确认编译通过
- Python：当前无统一测试 / lint 命令，需按改动接口做实际请求验证，并核对双端兼容性（见 [09-API契约与路由](09-API契约与路由.md)）
