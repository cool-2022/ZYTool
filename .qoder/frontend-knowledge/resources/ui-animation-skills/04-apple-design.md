# Apple Design

Apple 如何构建"不再像一台电脑、开始像你身体的延伸"的界面。本知识来自 Apple 的 WWDC 设计演讲——主要是 *Designing Fluid Interfaces*（WWDC 2018）——经过提炼并翻译到 Web 平台（CSS、Pointer Events、`requestAnimationFrame`、Motion/Framer Motion 等弹簧库）。

贯穿始终的主线：**当运动从当前屏幕上的值开始、继承用户的速度、向前投射惯性、并且可以在任意瞬间被抓住并反向时，界面就活了。** 弹簧是让这一切自然发生的工具，因为它天生可中断、感知速度。

## 核心思想

> "当我们让界面对齐人类的思考和运动方式时，神奇的事情发生了——它不再像一台电脑，而开始像我们自身的无缝延伸。"

当界面表现得像物理世界时，它就是流畅的：事物即时响应、连续运动、携带惯性、在边界处产生阻力、并且可以在运动中途被改变方向。下面所有内容都是通向这个目标的方法。

Apple 把设计定位为服务四种人类需求：**安全/可预测、理解、成就、愉悦。** 这里的每条规则都服务于其中之一。

## 1. 响应——消灭延迟

一旦出现迟滞，直接操控的感觉就会"断崖式崩塌"。响应是其他一切的地基。

- **在 pointer-down 时响应，而不是在释放时。** 按钮被按下的瞬间就高亮。等到 `click`/touch-up 才给反馈会让人觉得死气沉沉。
- **警惕每一处延迟。** 审计 debounce、人为定时器、过渡等待，以及 ~300ms 的点击延迟。输入路径上任何非必要的东西都是回退。
- **反馈必须在交互*过程中*连续，而不只是在结束时。** 对拖拽、滑块、抽屉，全程让 UI 与指针 1:1 同步更新——绝不要只在手势完成后才播放动画。

```css
/* 反馈发生在按压瞬间，而且是即时的 */
.button:active {
  transform: scale(0.97);
  transition: transform 100ms ease-out;
}
```

## 2. 直接操控——1:1 跟踪

> "触摸与内容应该一起移动。"

用户拖拽某个东西时，它必须黏在手指上——并且尊重*抓取点*的偏移。抓住时吸附到元素中心会立刻打破幻觉。

- 使用 Pointer Events 配合 `setPointerCapture`，这样即使指针移出元素边界，跟踪也能继续。
- 维护一小段**速度/位置历史**（最近几个 `pointermove` 事件），而不只是当前点——释放时你需要速度。

```js
el.addEventListener('pointerdown', (e) => {
  el.setPointerCapture(e.pointerId);
  const grabOffset = e.clientY - el.getBoundingClientRect().top; // 尊重抓取位置
  // ...记录位置 + 时间戳历史，用于计算速度
});
```

## 3. 可中断性——最重要的单一原则

> "思考和手势是并行发生的。"

每个动画都必须可以在任意时刻被中断和转向。用户必须能在元素飞行途中抓住它并反向，而不必等动画播完。一个正在关闭的弹窗被用户再次抓住时，应该跟随手指——而不是先关完再重新打开。

- **绝不要在过渡期间锁定输入。**
- **永远从*呈现值*（当前值）开始动画，绝不要从目标值开始。** 中断时，读取元素当前屏幕上的实时 transform，从那里开始新动画。从逻辑值/目标值开始会产生可见的跳变。
- **任何手势驱动的东西都避免用 CSS transition 和 `@keyframes`**——它们无法在飞行途中被平滑抓住和反向。弹簧默认从当前值开始动画，这正是中断所需要的。
- **手势反向时，混合速度——不要硬切。** 在反向时用新动画替换旧动画会造成速度不连续，像"撞砖墙"。能在重新定向时携带速度的弹簧库可以避免它。（这就是 iOS 原生 *additive animations* 做的事；在 Web 上，选择一个能从当前速度重新定向的弹簧库。）
- **把 2D 运动分解为独立的 X 和 Y 两个弹簧。** 对 2D 距离用单个弹簧，当 X 和 Y 速度不同时会失同步。

## 4. 行为优于动画——用弹簧

> "把动画看作你和对象之间的对话，而不是界面预先写好的剧本。"

预先编排、固定时长的动画无法响应新输入。弹簧可以——新输入只是改变目标，运动保持连续。凡是用户能触碰的东西，都用弹簧。

Apple 刻意用两个对设计师友好的参数替换了物理三元组（质量/刚度/阻尼）。用这两个参数思考：

- **Damping ratio（阻尼比）**——控制过冲。`1.0` = 临界阻尼，无回弹，平滑落定。`< 1.0` = 过冲并振荡。越低越弹。
- **Response（响应）**——值到达目标的快慢，单位为秒。越低越利落。**这不是"时长"**——弹簧没有固定时长；它的落定时间由参数涌现出来。

**默认值：**
- 大多数 UI 从 **damping `1.0`**（临界阻尼）开始——优雅且不分散注意力。
- **只有当手势本身携带惯性时**（快速甩动、投掷、拖拽释放）才加回弹（**damping ~`0.8`**）。一个刚淡入的菜单出现过冲会感觉不对；一张被你甩出去的卡片出现过冲会感觉对。

**Apple 实际使用的具体数值：**

| 交互 | Damping | Response |
| --- | --- | --- |
| 移动 / 重新定位（如画中画 PiP） | `1.0` | `0.4` |
| 旋转 | `0.8` | `0.4` |
| 抽屉 / 底部面板 | `0.8` | `0.3` |

**Web 映射（Motion / Framer Motion）：** `bounce` + `duration` 弹簧 API 与 Apple 的 damping + response 高度对应。安全的默认风格是到处用 `damping: 1.0` 弹簧；只为惯性驱动的物理交互保留回弹。

```js
import { animate } from 'motion';

// 临界阻尼默认（无过冲）
animate(el, { y: 0 }, { type: 'spring', bounce: 0, duration: 0.4 });

// 惯性交互——一点回弹，只因为前面有一个甩动
animate(el, { y: target }, { type: 'spring', bounce: 0.2, duration: 0.4 });
```

## 5. 速度交接——拖拽与动画之间的接缝

手势结束时，动画必须**以手指的精确速度继续**，这样拖拽和动画之间没有可见的接缝。这是区分"流畅"和"还行"的最关键细节。

把指针的释放速度作为弹簧的初始速度传入。有些弹簧 API 需要**相对**速度——用到目标的剩余距离做归一化：

```
relativeVelocity = gestureVelocity / (targetValue − currentValue)
```

示例：元素在 `y=50`，目标 `y=150`（还剩 100px），手指以 50px/s 移动 → 弹簧初始速度 = `50 / 100 = 0.5`。Framer Motion / Motion 直接接受绝对 px/s 速度（`velocity` 选项），所以通常直接传原始值。

## 6. 惯性投射——动画到手势*将要去*的地方

> "用小输入产生大输出。"

不要从*释放点*吸附到最近边界。用速度**投射静止位置**——和滚动减速完全一样——然后吸附到离投射点最近的目标。正是这让甩动感觉像把元素"扔"了出去。

Apple 的精确投射函数（来自 *Designing Fluid Interfaces* 示例代码）：

```js
// decelerationRate ≈ 0.998 对应普通滚动手感；0.99 更利落
function project(initialVelocity /* px/s */, decelerationRate = 0.998) {
  return (initialVelocity / 1000) * decelerationRate / (1 - decelerationRate);
}

const projectedEndpoint = currentPosition + project(releaseVelocity);
const target = nearestSnapPoint(projectedEndpoint);   // 从投射点选目标
animateSpringTo(target, { velocity: releaseVelocity }); // 然后交接速度（§5）
```

注意：物理教科书里的 `v²/(2·decel)` *不是* Apple 实际使用的——用上面的指数衰减形式。这是优秀底部面板和轮播（Vaul、Embla）的标准行为。

## 7. 空间一致性——对称路径、锚定原点

> "如果某样东西以某种方式消失，我们期望它从来的地方出现。"

- **进入和退出走同一条路径。** 从右侧滑入的面板必须向右侧关闭。右进 / 下出会让人感觉脱节和困惑。
- **把交互锚定到它的来源。** 菜单、气泡、面板应该从触发它的元素处生长出来——把 `transform-origin` 设为触发元素，让按钮和内容之间的空间关系一目了然。（这与气泡从触发元素而非自身中心缩放是同一个原点感知原则。）
- **可逆过渡要镜像缓动**，让去程路径与回程路径匹配（两个方向使用互逆的 cubic-bézier 控制点）。

## 8. 朝手势方向给出暗示

人类会从轨迹预测最终状态。中间运动应该预示事物的去向——控制中心的模块会"朝着你的手指生长并展开"。让中间帧指向结果，而不是盲目地向结果插值。

## 9. 橡皮筋效应——软边界

在边缘处，渐进地抵抗而不是硬停。硬停读起来是"卡死了"；连续的阻力读起来是"有响应，但这里没有更多内容了"。施加随用户拖过边界越远而越大的阻尼。

```js
// 越过边界越远，元素跟随得越少——真实物体在停下前会减速
function rubberband(overshoot, dimension, constant = 0.55) {
  return (overshoot * dimension * constant) / (dimension + constant * Math.abs(overshoot));
}
```

## 10. 手势设计细节（"手感"检查清单）

- **点按（Tap）：** 在 touch-*down* 时高亮（即时），在 touch-*up* 时确认。在目标周围加 ~10px 的迟滞/命中扩展，并允许通过拖走再拖回来取消。
- **拖拽/滑动：** 在确定方向前要求一个小的移动阈值（迟滞，~10px），然后 1:1 跟踪。
- **从第一次移动起就并行检测所有可能的手势**，意图明确后果断取消落选者。避免只报告*最终*状态的识别器（`swipeleft` 类事件）——它们丢弃了你做反馈所需的连续跟踪。
- **最小化消歧延迟。** 双击检测不可避免地延迟单击；只在真正存在双击的地方付出这个代价。

## 11. 帧级平滑

平滑关乎*帧里有什么*，而不只是帧率。

- 保持每帧的位置变化低于感知阈值，以避免频闪（strobing）。
- 对非常快的运动，微妙的**运动模糊 / 拉伸**能编码速度感，比一条生硬的锐利残影读起来更好。
- `requestAnimationFrame` 是 Web 的显示同步时钟（Apple 用 `CADisplayLink`）。只动画合成器友好的属性——`transform` 和 `opacity`——并在运动即将发生时用 `will-change` 提示。

## 12. 材质与景深——半透明传达层级

Apple 把半透明材质用作浮动的功能层，带来结构而不抢夺焦点。在 Web 上用 `backdrop-filter` 近似。

- **把导航/工具栏/面板构建为半透明层**（`backdrop-filter: blur()` + 半透明背景），内容在其下方滚动——而不是占据固定一条的不透明横条。
- **材质重量编码层级：** 更深/更重的材质分隔结构区域（侧栏）；更轻的材质把注意力引向交互元素（按钮）。**绝不要把浅色半透明表面叠在另一个浅色半透明表面上**——可读性会崩塌。
- **更大的表面应该读起来更厚：** 比小芯片更强的模糊 + 更深的阴影。考虑上下文感知的阴影——在繁杂/文本内容上方用更重的阴影以分离，在纯色背景上用更轻的。
- **用变暗聚焦，用分离保流。** 模态任务把表面配一个变暗的遮罩（scrim），并把背景向后/向下推。并行的、非阻塞的面板使用半透明和偏移*而不*加遮罩，这样流程不被打断。对叠放的面板，逐层把父层变暗并向后推。
- **Vibrancy 让文本在变化的背景上保持可读。** 在模糊/半透明表面上，不要用平灰色文本——用更高对比度、略重的字重、以及轻微增大的字距。颜色放在实色层上，而不是半透明前景上。
- **滚动边缘效果，而不是生硬的分隔线。** 不要在吸顶头部下放一条 1px 边框，而是在内容与浮动 UI 交接处淡入一个小的模糊/渐变遮罩——只在浮动 UI 真正与内容重叠的地方。
- **材质化，而不只是淡入。** 对玻璃/模糊表面，进入/退出时同时动画模糊半径和缩放，让表面读起来像真实材质到来，而不是普通的透明度淡入。

```css
.toolbar {
  background: rgba(255, 255, 255, 0.6);
  backdrop-filter: blur(20px) saturate(180%);
  border-top: 1px solid rgba(255, 255, 255, 0.4); /* 明亮的顶边 = 光照在材质上 */
}
```

## 13. 多模态反馈——运动 + 声音 + 触觉

组合感官的三条规则（来自 *Designing Audio-Haptic Experiences*）：

1. **因果性（Causality）**——必须显而易见是什么引起了反馈。在真正的因果事件上触发（开关翻转、项目吸附到位），并让反馈的特征匹配动作的物理感。
2. **和谐性（Harmony）**——视觉、声音和触觉必须在**同一帧**触发。它们之间的延迟会摧毁幻觉。不要让 CSS transition 拖慢音频/触觉（Vibration API）。
3. **实用性（Utility）**——只在值得的地方加反馈。把触觉/声音留给有意义的时刻（成功、错误、确认、吸附）。过度反馈会训练用户忽略所有反馈。

## 14. 减弱动效与无障碍

减弱动效不意味着*没有*反馈——它意味着更温和、不前庭刺激的等价物。响应三个独立信号并把它们固化进组件：

- **`prefers-reduced-motion: reduce`**——用短的透明度**交叉淡变或静态过渡**替换滑动/弹簧/视差。去掉弹性/过冲。保留有助于理解的透明度/颜色变化。
- **`prefers-reduced-transparency: reduce`**——让半透明表面更磨砂/实色：提高背景不透明度，去掉模糊。
- **`prefers-contrast: more`**——近实色背景 + 明确的对比边框。

另外：避免全视口移动的背景、慢速循环振荡（接近 0.2 Hz / 每 5 秒一个周期）、以及突兀的亮度跳变（明暗主题切换要缓动）。让大型移动对象在移动途中半透明，并在大幅重定位期间把大表面淡出、落定后淡回。

```css
@media (prefers-reduced-motion: reduce) {
  .sheet { transition: opacity 200ms ease; transform: none !important; }
}
@media (prefers-reduced-transparency: reduce) {
  .toolbar { background: white; backdrop-filter: none; }
}
```

## 15. 排版——视觉字号、字距、行距

Apple 设计的字体会随字号改变形状；同样的纪律适用于 Web。（来自 *The Details of UI Typography*，WWDC 2020。）

- **Tracking（letter-spacing）是字号相关的——绝不要所有字号用一个值。** 大号展示文本需要*负*字距（字母变大后读起来间距过开）；小文本需要轻微*正*字距以保证可读性。固定的 `letter-spacing` 总会在某处出错。收紧标题，正文保持接近 `0`。
- **Leading（line-height）与字号反向相关。** 大标题收紧，正文放松。对上行/下行笔画高的文字系统增大它；对密集、信息量大的 UI 收紧它。
- **用字重 + 字号 + 行距的组合构建层级，** 而不是只靠字号。用字重强调——它增加存在感而不占更多空间。
- **尊重用户的文字大小设置**（Dynamic Type）。让布局*随*文本缩放——间距用 `rem`/`em` 而不是固定 px——这样更大的字体不会破坏布局。
- **默认先用平台系统字体**，再考虑自定义字体；系统字体已经内置视觉字号、字距表和可读性调优。有理由才覆盖。

```css
:root { font: 100%/1.5 system-ui, sans-serif; } /* 正文：系统字体，舒适行距 */

.display {
  font-size: clamp(2rem, 5vw, 4rem);
  line-height: 1.05;        /* 大文本收紧行距 */
  letter-spacing: -0.02em;  /* 变大后用负字距 */
  font-optical-sizing: auto;
}
```

## 16. 设计根基——八大原则

上面的动效与工艺服务于 Apple 的八大设计原则（*Principles of Great Design*，WWDC 2026）。把它们作为你推理时使用的名称：

1. **目的（Purpose）。** 有意图地做；决定*不*做什么。每个功能都在索取用户的时间、注意力和信任——只在有回报的地方花这笔预算。
2. **掌控（Agency）。** 让人保持控制：提供选择，不强迫单一路径。用宽容来支撑——失误容易撤销，确认对话框只用于真正破坏性、不可逆的操作（谨慎使用；滥用会训练人直接点过去）。
3. **责任（Responsibility）。** 为用户的利益行事。隐私：在正确的时机、只请求所需、透明地请求。安全：预判误用与伤害——尤其是 AI（一个感知过敏的食谱应用绝不能推荐有害食材）。加预览、确认、免责声明；砍掉风险大于价值的功能。
4. **熟悉（Familiarity）。** 建立在人们已知的事物上。使用既不过于字面也不过于抽象的隐喻（垃圾桶意味着删除），并尊重它们的物理特性。保持一致：看起来相同的东西必须行为相同、位置相同（macOS 上关闭永远在左上角），这样人们能预测接下来发生什么。只有能证明更好时才打破熟悉模式——然后要测试，不要想当然。
5. **灵活（Flexibility）。** 为不同上下文、设备和全部能力范围设计。适配平台（iPhone = 快速触摸；桌面 = 精确指针控制的深度工作流）和情境。包容地设计（年龄、语言、专业程度、无障碍）。当没有单一布局适合所有人时，让人们个性化——重排控件、隐藏不用的东西。
6. **简单——不是极简（Simplicity — not minimalism）。** 去掉不必要的东西，让核心目的显现；把所有东西埋在一个地方看起来极简但并不简单。要简洁（平实语言、无行话、更少步骤）且清晰（用层级——顺序、间距、对比——让最重要的东西最显眼）。每个元素都要挣得自己的位置；有时*增加*上下文反而简化（显示剩余时间的视频进度条）。先展示常见路径，高级选项放深一层。
7. **工艺（Craft）。** 对细节毫不妥协的关注建立信任。优美的排版、适配明暗的颜色、清晰的图标、以及给出即时自然反馈的响应式动画。没有什么是随机的——每个间距、时长、对齐值都是你能辩护的刻意选择。滚动手抖、图标错位、旋转时布局崩坏，都读起来像漫不经心。工艺需要迭代和持久——随功能与硬件变化持续演进设计。
8. **愉悦（Delight）。** 是把其他七项做对的结果，而不是贴在顶上的彩纸。决定你想让人们感受到的情绪（平静、自信、兴奋），并在每个决策中强化它。

服务于这些原则的战术规则：

- **反馈有四种：** 状态、完成、警告、错误。确认有意义的操作、暴露进行中的状态、在问题前警告、内联校验（而不是提交时才校验）。
- **寻路（Wayfinding）。** 每个屏幕都应回答：我在哪？我能去哪？那里有什么？我怎么出去？绝不要困住用户。
- **分组与映射（Grouping & mapping）。** 邻近暗示关系；把控件放在它影响的东西附近，并按它们改变的对象来排布控件。如果你需要一个标签来解释控件，说明映射很弱。
- **直接、具体的标签胜过安全的笼统标签。** 用内容命名导航项（"Progress"、"Library"），而不是笼统的大伞（"Home"）。具体性创造可预测性。

## 17. 流程

- **交互式原型——一个可交互的 demo 胜过"一百万张静态设计稿"。** 你通过构建和把玩来发现界面；可工作的原型还设立了具体的标杆，防止平庸的最终实现。
- **交互与视觉一起设计。** "你不应该能说出一个在哪里结束、另一个在哪里开始。" 运动不是像素画完之后再加的一层。
- **在真实情境中用真人测试**，并用新鲜的眼光评审运动——慢速播放 / 逐帧播放，捕捉全速下看不见的东西。

## 速查表

| 需求 | 技术 | 具体值 |
| --- | --- | --- |
| 默认 UI 弹簧 | 临界阻尼，无过冲 | `damping 1.0`，`response 0.3–0.4` |
| 惯性 / 甩动弹簧 | 欠阻尼，轻微回弹 | `damping ~0.8`，`response 0.3–0.4` |
| 手势 → 弹簧速度 | 交接释放速度 | 归一化时 `gestureVelocity / (target − current)` |
| 甩动落点 | 投射惯性 | `current + (v/1000)·d/(1−d)`，`d ≈ 0.998` |
| 干净地中断 | 从呈现值（实时值）开始 | 读取屏幕上的 transform |
| 避免反向"撞墙" | 重新定向时携带速度 | 混合速度的弹簧 |
| 可逆过渡 | 镜像缓动曲线 | 互逆 cubic-bézier |
| 决定反向还是确认 | 用速度**符号**，不用位置 | 在释放时 |
| 1:1 拖拽 | Pointer Events + capture | 尊重抓取偏移 |
| 反馈 | pointer-down 时、连续 | 绝不只在结束时 |
| 边界 | 橡皮筋，不硬停 | 渐进阻力 |
| 半透明 UI 件 | `backdrop-filter` 层 | 内容在其下滚动 |
| 字距 | 字号相关，绝不固定 | 大文本收紧（`-0.02em`），正文接近 `0` |
| 减弱动效 | 交叉淡变，不滑动/弹簧 | `@media (prefers-reduced-motion)` |
